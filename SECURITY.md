# Security

## Reporting a vulnerability

Please do **not** open a public issue. Use GitHub's private vulnerability reporting
(Security tab -> "Report a vulnerability") of this repository. You get an answer within a few days.

## Threat model

The plugin runs inside a Hermes Kanban worker and talks to LLM providers. Assets and how they are protected:

| Threat | Why it matters | Control |
|---|---|---|
| **Card text is untrusted.** It can come from mail, web pages or other agents. | A card could ask the plugin to run a command or leak code. | `verify:` runs only for cards created by `verify.trusted_creators`, never through a shell (`shlex`), only commands whose first word is in `verify.allow`, with a scrubbed environment, on a background thread in its own process group (killed after `verify.timeout_s`, default 600 s). `python3 -c` is still arbitrary code: the creator check is the real control. |
| **Code and logs leave the machine** when the advisor asks a remote model. | Secrets in tool output or files. | The advisor is **off** until you enable it AND opt a board or card in. Every prompt passes Hermes' `redact_for_egress` plus a URL-credential scrub; `EgressRedactionTest` pins the shapes (GitHub/OpenAI/Anthropic/OpenRouter/AWS keys, bearer headers, password assignments, `scheme://user:pass@host`). Board tool results are filtered out. `[local-only]` on a card always wins. The redactor is pattern based: an unusual secret format can pass, so do not enable the advisor on boards that handle secrets in plain text. |
| **Pre-flight** asks a remote model before a critical command runs. | A command (or card text) could leak into the prompt, or a model could block a needed command. | Pre-flight is active **only where the advisor is** (board opt-in or card marker) and never on `[local-only]` cards, non-critical commands, or outside Kanban workers. The card and command are redacted before the question leaves. The log stores only the command hash, not the command. A HOLD is a persistent block that only a human release lifts — a model never releases its own hold; a timeout, a down provider, an unparseable answer or the cap lets the command run (fail-open). |
| **Mom answers worker questions** (`calling_mom.answer`, off by default). | With it on, a model answers a question a worker asked a person and **unblocks the card**; a wrong answer steers the worker, and the question, the card text and the last comments go to a remote model. | Own switch and own board list (`answer.enabled`, `answer.boards`), separate from the advisor. Only the worker's own `needs_input` block counts (a block by a person, or one Hermes re-kinded, is skipped). The fast path decides without a model: `[local-only]` and `[human]` cards are skipped; a question or card that matches the critical risk list or `rules.HUMAN_TOPICS` (credentials and secrets, payments and money, legal, personal data, publishing in the owner's name) and a card with an active pre-flight HOLD **never get an answer**, at most a brief for the person. The prompt is redacted like every other. At most `answer.max_per_card` per card and the advisor's daily caps; Olymp 1 per card and 6 per day. Error or timeout: the card stays blocked and unchanged, no retry. Mom can never release a HOLD: `answer_card(allow_once=True)` is for a person only (CLI `hermes calling-mom answer`). The log stores outcome, reason, counts and ids, never the question or the answer. |
| **Precedents** (`answer.precedents`, on by default, only where answers are on). | The one place the plugin stores prose: your answer to Mom's brief and the question, in `logs/calling-mom-precedents.jsonl`. Text you typed can hold something sensitive, and a stored answer steers a later answer. | Redacted with `redact_for_egress` plus the URL-credential scrub before it is written, at most 500 characters per text, local file only. A question or answer that matches `rules.HUMAN_TOPICS` and a `[local-only]` card are never stored. Mom sees at most three entries, labelled as data (the prompt goes through the same egress redaction), and never for a brief-only question. `hermes calling-mom precedents` lists, `forget <id>` deletes one, `clear` deletes all; `answer.precedents: false` stops storing and using. The observation log stays prose-free. |
| **Desktop backend routes** (`dashboard/plugin_api.py`, `/api/plugins/calling-mom/`). | The Desktop page reads cards and answers for you; a route is a door. | They live in the gateway and inherit its authentication. They read the plugin log (counts, ids, verdicts) and, read-only, the Kanban boards; `GET /cards` returns badge names and no text, `GET /needs-you` returns the title and the `[for you]` brief or hold of cards on opted-in boards only. The one write is `POST /answer`, which is `answer_card(by="desktop")` and nothing else: a `[you via calling-mom]` comment, an allowance for the held command when you pressed **Allow once**, unblock of that card, and a `human_answer` log row. It refuses boards that do not exist (a name is never turned into a path), boards that did not opt in, cards that are not blocked or carry no brief or hold. Mom never calls it. The Desktop half uses the plugin SDK only (`ctx.rest` to these routes, `ctx.storage` for the list of holds you chose to keep). |
| **Model override** lets a plugin call any model on your credentials. | Cost and data exposure. | Hermes grants it only through `plugins.entries.calling-mom.llm.allowed_models/allowed_providers`. `hermes calling-mom setup` only ever **adds** entries and shows what it writes. |
| **Runaway spend.** | A loop could call the expensive model. | Olymp: hard limits per card and per day (calls). Mom: per-card budgets, daily USD and token caps. Failures are fail-open (the worker continues). |
| **Observation log** | A log is a data store. | (Precedents are a separate, disclosed file, see above.) It stores hashes, counts, token numbers and tool names, no content. The 1.5 rows (`touch`, `own_write`, `advice_feedback` anchors) keep author ids, event kinds, times and anchor hashes, never text. Outside help and chat waits are counts and ids only; the sweep reads the Kanban store read only, through one read in `_core.py` that `hermes calling-mom doctor` checks (`board read`). `hermes calling-mom report` and `GET /summary` only count these rows. |
| **Config** | A plugin that edits config is a risk. | Only the commands you run yourself (`setup`) write config, with the values you picked. Hooks never do. |

## Data flows

Every flow that carries data out of the process or into a file, in 1.4. "Remote" means a model provider you configured
for Mom or Olymp. Each prompt passes Hermes' `redact_for_egress` and the URL-credential scrub first. `[local-only]` on a
card stops every flow marked "remote" for that card.

| Flow | Leaves the machine? | What is sent or stored | Switch |
|---|---|---|---|
| Advice on a stuck signal, a risky command, a completion check, `SECOND-OPINION:` | Remote: Mom, and Olymp after `ESCALATE` | Card text, the last tool steps, the signal. Redacted, cut to `advisor.context_chars`. | `advisor.enabled` + a board or `[advisor]` on the card |
| Late advice | No | The answer, written as a card comment and added to the worker's next tool result. | follows the advisor |
| Pre-flight check | Remote: Mom | The card title and the first 800 characters of its text, the command, the last tool steps. The log keeps only the command hash. | `preflight.enabled` (needs the advisor) |
| Pre-flight HOLD | No | A card comment with Mom's reason, and a stored block (task, command hash) in the plugin state. A person releases it. | follows pre-flight |
| Worker question | Remote: Mom, then Olymp if she escalates | The question, the card text and the last comments. Never for `[local-only]`, `[human]`, credentials, money, legal, personal data, publishing, critical commands or a held card (a brief at most). | `answer.enabled` + `answer.boards` |
| Brief and answer | No | A `[for you]` brief and your `[you via calling-mom]` answer, as card comments. | follows answers |
| Precedents | No (it reaches Mom only inside a later question prompt, redacted) | Your answer and the question, as text, 500 characters each, in `logs/calling-mom-precedents.jsonl`. | `answer.precedents`; `hermes calling-mom precedents` lists and deletes |
| `verify:` command | No | Runs a command from the card on this machine. Only for cards by `verify.trusted_creators`, first word in `verify.allow`. The log keeps the state, the exit code and the time. | `verify.*` |
| Observation log | No | Hashes, counts, tool names, token numbers (`worker_usage`), verdicts, advice results and anchor hashes (`advice_feedback`). No prompt, no command, no text. Trimmed at 5 MB. | `observe` |
| Outside help count (the sweep) | No | Reads comments and events of opted-in boards, read only, and logs `touch` rows: the author id of a comment (a profile or surface id), the kind of a board event, the store id (dedupe), the time and, for a card waiting in triage or on a question, the seconds it waited. Never comment text. Board events carry no actor in the store: they count as `unattributed`. What calling-mom writes itself is logged as `own_write` (kind, card, store id) and not counted. | board opt-in (`advisor.boards` or `answer.boards`) |
| Chat waits | No | `on_human_input_request` / `on_human_input_resolved` in any session of the profile: the kind of wait (`clarify`, `approval`, `sudo`, `other`), seconds, outcome, an opaque request id. The prompt and your answer in the payload are never read. | `count.chat_waits` (off by default; `setup` asks) |
| Attention report and `GET /summary` | No | A count over the log rows and a read-only list of cards of opted-in boards. | none (read only) |
| Desktop page | No (your own gateway) | Reads the log and the boards; one write, `POST /answer`, when you press a button. | install the Desktop half or not |
| Metrics push | Your Pushgateway | Counts and ages only (see the metric families). | `metrics.pushgateways` |
| Demo kit (`scripts/demo.py`) | No | Four cards on a board of its own and a scratch folder with a bare **local** git remote. It refuses to run if `origin` is not a folder under the scratch root, and deletes only a folder that carries its marker file. Its cards send data to Mom like any other card on an opted-in board. | run it or not |

The plugin sends nothing to any server of its own. It has no telemetry.

Out of scope: the security of Hermes itself and of the providers you configure.
